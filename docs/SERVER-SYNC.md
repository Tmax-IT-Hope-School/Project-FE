# 이 기기의 데이터를 서버와 맞추기 (#516)

카드 · 공부 기록 · 목표 · 미루기/실패/휴식은 **이 기기(localStorage)에 먼저 저장**하고, 서버(BE)와는 **뒤에서 맞춥니다.**
이 문서는 "무엇이 언제 서버로 가는지" 와 "새 코드를 쓸 때 지킬 것" 을 정리한 것입니다. (2026-10-17, FE PR #519 · #523 · #524 · #525 · #526)

> 한 줄 요약: **카드 · 목표는 꼭 `saveCards` · `saveGoals`(또는 그 훅)로 저장한다. 그래야 서버로 간다.**
> (고정 일정 입력과 그 동기화(`lib/fixedBlockSync.ts`)는 2026-10-18 에 지웠습니다. 서버의 `/api/v1/fixed-blocks` 는 그대로입니다.)

---

## 1. 왜 "이 기기 먼저" 인가요?

- 화면은 예전처럼 localStorage 를 읽고 씁니다. 그래서 **화면 코드는 거의 바뀌지 않았고**, 서버가 꺼지거나 인터넷이 끊겨도 앱은 그대로 돕니다.
- 못 보낸 것은 **보낼 목록**에 남겨 두었다가, 다음에 앱을 열 때(또는 1분 뒤) 다시 보냅니다.
- 서버에 데이터가 있어야 BE 의 AI(하루 계획 · 카드 제안 · 통화 · 리포트)가 "타이머가 잰 숫자" 로 말할 수 있습니다.
- 체크인(#321, `lib/checkInsApi.ts`)도 같은 방식입니다.

**테스트 로그인은 서버를 쓰지 않습니다.** 진짜 구글 로그인일 때만 맞춥니다. (`useIsServerData()`)

## 2. 무엇이, 어떻게 가나요?

| 데이터                         | 서버 주소 (BE `docs/API.md`)                            | 방향                   | 규칙 파일                | 보낼 목록 · 표시 (localStorage) |
| ------------------------------ | ------------------------------------------------------- | ---------------------- | ------------------------ | ------------------------------- |
| 카드                           | `/api/v1/cards`                                         | 보내기 + **받아 오기** | `lib/cardSync.ts`        | `study-card-sync-pending`       |
| 목표                           | `/api/v1/goals`                                         | 보내기 + **받아 오기** | `lib/goalSync.ts`        | `study-goal-sync-pending`       |
| 공부 기록 (타이머 · 노는 기록) | `POST /api/v1/study-sessions`                           | **보내기만**           | `lib/sessionSync.ts`     | `study-session-sync`            |
| 미루기 · 실패                  | `POST /api/v1/cards/{id}/postpone` · `/fail`            | **보내기만**           | `lib/markSync.ts`        | `study-mark-sync`               |
| 사후 입력                      | `POST /api/v1/cards/{id}/late-entry`                    | **보내기만**           | `lib/markSync.ts`        | `study-mark-sync`               |
| 휴식 처리                      | `POST /api/v1/rest-days/{date}`                         | **보내기만**           | `lib/markSync.ts`        | `study-mark-sync`               |
| 확인 문제 결과 (#653)          | `POST /api/v1/quiz-results` · `GET /quiz-results/stats` | 보내기 + **통계 받기** | `lib/quizResultsApi.ts`  | `study-quiz-result-sync`        |
| 학년 · 반 (2026-10-31)         | `GET` · `PUT /api/v1/auth/school-class`                 | 보내기 + **받아 오기** | `lib/schoolClassSync.ts` | `study-school-class-unsent`     |

- **받아 오기**: 앱을 열 때 서버의 목록을 받아(TanStack Query `useQuery`), 다른 기기에서 만들거나 고치거나 지운 것을 이 기기에도 반영합니다.
- **보내기만**: 서버에 "고치기" 주소가 없어서 받아 오지 않습니다. 받아 오면 "모든 기록 지우기" 로 지운 기록이 다른 기기에서 다시 들어올 수 있기 때문입니다.
- 서버에 올라간 것에는 **서버 번호**(`serverId`)가 붙습니다. (`Card.serverId` · `Goal.serverId` · `FixedBlock.serverId`)
- 다른 기기에서 만든 것은 id 가 `card-s7` · `goal-s4` · `fixed-s9` 처럼 됩니다. (s 뒤가 서버 번호)
- **학년 · 반**: 예전에는 이 기기에만 있어서 새 기기에서 로그인하면 홈 시간표가 안 보였습니다. 앱을 열 때 이 기기에 못 보낸 반이 있으면 보내고, 없으면 서버의 반을 받아 둡니다. 설정 · 온보딩에서 바꾸면 바로 보냅니다. 홈 · 설정은 `useSchoolClass` 로 읽어서 받아 오는 즉시 다시 그려집니다.
- **통계 받기**: 확인 문제 결과는 서버가 하나하나 돌려주지 않고 과목 · 단원 · 날짜별 맞은 수만 줍니다. 기록 탭 · 문제 풀이 리포트가 받을 때 이 기기에서 보낸 몫을 빼고 더합니다. 그날 푼 것만 보냅니다. ([HISTORY-REPORT.md](./HISTORY-REPORT.md))

모든 맞추기는 `components/layout/Layout.tsx` 에서 훅 한 번씩으로 켭니다: `useCardSync` · `useGoalSync` · `useSessionSync` · `useMarkSync` · `useQuizResultSync` · `useFixedBlockSync` · `useSchoolClassSync`.

## 3. 흐름 (카드를 예로)

```
화면에서 카드 저장 (useCards 의 addCard · updateCard)
  → saveCards(cards)                      lib/cards.ts — localStorage 에 저장 + 'study-cards-changed' 이벤트
  → useCardSync 가 이벤트를 받음           바뀐 카드를 "보낼 목록" 에 적음 (markCardChanges)
  → 0.8초 뒤 pushPendingCards()            하나씩 POST(처음) / PATCH(고침) / DELETE(지움)
  → 성공하면 카드에 serverId 를 붙여 저장   saveCards(…, 'server') — 'server' 저장은 다시 보내지 않음
  → 실패(인터넷 끊김)하면 목록에 남김       다음에 앱을 열 때 다시
```

앱을 열 때는 `GET /cards` 로 받아 `mergeServerCards` 규칙으로 맞춥니다.

| 이 기기의 카드                    | 결과                                      |
| --------------------------------- | ----------------------------------------- |
| 서버 번호 없음 (아직 안 올라감)   | 그대로 두고 올림                          |
| 이 기기에서 고쳤는데 아직 못 보냄 | **이 기기의 것이 이김**                   |
| 그 밖                             | 서버의 내용으로 맞춤 (다른 기기에서 고침) |
| 서버 번호가 있는데 서버에 없음    | 다른 기기에서 지운 것 → 이 기기에서도 뺌  |
| 이 기기에 없는 서버 카드          | 다른 기기에서 만든 것 → 더함              |

목표도 같은 규칙입니다. (목표는 서버에 지우는 주소가 없어서, 서버가 모르는 목표는 빼지 않고 다시 올립니다)

## 4. 순서가 중요한 곳

- **카드 → 공부 기록 · 미루기 · 사후 입력**: 서버는 내 카드 번호로만 받아서, 카드가 서버에 올라간 뒤에 보냅니다. 그 전에는 기다립니다.
- **목표 → 카드**: 카드에는 목표의 **서버 번호**를 보냅니다. 목표가 아직 안 올라갔으면 "목표 없음" 으로 보내고, 목표가 올라가면 그 목표의 카드를 다시 보냅니다. (`markCardsOfGoal`)
- **미루기 → 카드 날짜 바꾸기**: 서버의 미루기는 "그날 하는 카드" 만 받고 1회성 카드를 직접 옮깁니다. 카드 날짜를 먼저 바꾸면 미루기가 거절되므로, **안 보낸 미루기가 있는 카드는 날짜 바꾸기를 기다립니다.** (`hasUnsentPostpone`)
- **공부 기록은 끝나고 10분 뒤**에 보냅니다. 끝난 직후 종료 팝업에서 체크 · 증빙을 더 붙이는데, 서버에는 보낸 기록을 고치는 주소가 없어서입니다.

## 5. 서버가 거절하면

| 서버의 답                           | 하는 일                                                                        |
| ----------------------------------- | ------------------------------------------------------------------------------ |
| 인터넷 끊김 · 시간 초과 · 서버 오류 | 멈추고 목록에 남김 → 다음에 다시                                               |
| 400 (값이 틀림)                     | 다시 보내도 같아서 목록에서 뺌. **이 기기의 것은 그대로**                      |
| 409 (한도 · 기한 · 시간 겹침)       | 목표(진행 중 3개) · 공부 기록 · 미루기 등은 목록에서 뺌. 이 기기의 것은 그대로 |
| 404 (서버에 없음)                   | 카드 · 목표는 다시 만듦(POST), 공부 기록 · 미루기는 뺌                         |

공부 기록을 보냈는데 답을 못 받아 다시 보내면 서버가 409(시간 겹침)를 줍니다. 이때는 같은 시작 · 끝 시각의 기록을 찾아 "이미 저장됨" 으로 봅니다. (`lib/sessionsApi.ts` 의 `createSession`) 그래서 두 번 저장되지 않습니다.

## 6. 새 코드를 쓸 때 지킬 것

- **카드 · 목표는 `saveCards` · `saveGoals` 로만 저장합니다.** 화면에서는 `useCards` · `useGoals` 의 함수를 쓰면 됩니다.
  `saveData('cards', …)` 처럼 저장소에 바로 쓰면 이벤트가 안 나가서 **서버로 가지 않고, 다른 화면도 모릅니다.**
- 위 훅들은 고칠 때 **저장소의 최신 목록을 다시 읽어서** 고칩니다. 화면이 들고 있는 옛 목록으로 통째로 덮어쓰면, 서버에서 받은 값(서버 번호 등)이 사라져서 같은 것이 서버에 두 번 만들어질 수 있습니다.
- 공부 기록은 `useStudySessions` 의 `addSession` 으로 저장하면 끝나고 10분 뒤에, 미루기 · 실패(`addCardMark`) · 휴식(`addRestDay`)은 1분 안에 서버로 갑니다.
- 새 데이터를 서버와 맞추고 싶으면 `lib/goalSync.ts` 를 본보기로 보세요. (가장 짧던 `lib/fixedBlockSync.ts` 는 2026-10-18 에 지웠고, git 기록에서 볼 수 있습니다)

## 7. 확인하는 법

- 개발자 도구 → Application → Local Storage 에서 위 표의 "보낼 목록" 이 비어 있으면 다 보낸 것입니다.
- Network 탭에서 `/api/v1/cards` 등의 요청을 볼 수 있습니다.
- 진짜 서버로 확인할 때: 구글 로그인 → 카드 · 목표 만들기 → **시크릿 창에서 같은 계정**으로 로그인해 보이는지 봅니다. Swagger 의 `GET` 주소로도 볼 수 있습니다.

## 8. 아직 안 된 것

- **설문 답(취침 · 기상 시각, 아침형/밤형)** 은 서버로 안 갑니다. 서버 설문 저장(`PUT /api/v1/onboarding`)이 새 온보딩에서 더 이상 묻지 않는 칸(목표 시험 · 시험 날짜)을 꼭 받아서입니다. BE 쪽을 바꾼 뒤 붙입니다. 그 전까지 AI 하루 계획은 기본 시간(07:00 ~ 00:00)으로 짭니다.
- **진척(목표의 `progressLog`) · 마지막 점검(`lastCheckedAt`)** 은 서버에 칸이 없어서 이 기기에만 있습니다.
- **다른 기기의 공부 기록 · 미루기 · 휴식**은 받아 오지 않습니다. (보내기만)
- 같은 기기에서 다른 구글 계정으로 바꿔 로그인하면, 이 기기의 카드 · 목표가 새 계정으로 올라갈 수 있습니다.
