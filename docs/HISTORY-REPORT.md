# 기록 탭 (History 리포트)

2026-10-24 에 기획이 바뀌어, 아래 탭이 **홈 · 카드 · 채팅 · 통계 · 기록** 5개가 되고 기록 탭은 **일간 · 주간 리포트** 화면이 됐습니다.
기준은 사용자가 준 **History 리포트 목업**(그림: [design/README.md](./design/README.md#11-기록-탭-history-리포트-2026-10-24))입니다. 예전 기획서(PLAN.md)와 다르면 목업이 우선입니다.

## 주소

| 주소                       | 화면                                                    | 파일                           |
| -------------------------- | ------------------------------------------------------- | ------------------------------ |
| `/records`                 | 일간 리포트 (기본)                                      | `src/pages/RecordsPage.tsx`    |
| `/records?view=weekly`     | 주간 리포트 (쉬어 간 주 포함)                           | 같은 파일                      |
| `/records?date=2026-10-17` | 그 날짜(일간) · 그 날짜가 든 주(주간)                   | 같은 파일                      |
| `/records/manual`          | 나 사용설명서 (옛 주소 `/manual` 도 여기로)             | `src/pages/ManualPage.tsx`     |
| `/records/quiz`            | 문제 풀이 리포트 (기록 탭 맨 아래 입구)                 | `src/pages/QuizReportPage.tsx` |
| `/stats`                   | 통계 탭 = 예전 기록 화면 (그래프 · AI 분석 · 사진 채점) | `src/pages/StatsPage.tsx`      |

## 숫자는 어떻게 정하나요? (`src/lib/historyReport.ts`)

숫자와 "한 줄" 문장은 모두 코드가 만듭니다. AI 를 부르지 않습니다.

| 칸                      | 규칙                                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------------ |
| 공부 시간               | 그날 공부 세션의 순공 합 (노는 기록 뺌, 하루는 새벽 4시 기준)                                          |
| 계획의 %                | 공부 시간 ÷ 그날 카드 길이의 합 (쉬는 날로 처리한 날은 계획 0)                                         |
| 과목별 시간             | 세션의 과목. 카드 타이머 세션은 과목이 비어 있어서 카드 제목 → 목표 제목에 든 과목 이름, 없으면 '기타' |
| 확인 문제 정답률        | 채팅 확인 문제 결과(`lib/studyQuiz.ts`) + 사진 채점(서버, '애매'는 뺌)                                 |
| **계획 완료한 날**      | 판정된 카드가 1장 이상이고, 쉰 카드를 뺀 모든 카드가 제때 · 늦게 · 나중에 적음 (`COMPLETE_RESULTS`)    |
| 총 N일                  | 그날까지 계획 완료한 날의 수 (스트릭이 아니라 누적, 끊겨도 0 으로 안 돌아감)                           |
| **쉬어 간 주**          | 다 지난 주 + 그 주 전에도 기록이 있음 + 공부한 날 2일 이하 (`REST_WEEK_MAX_STUDY_DAYS`)                |
| **첫 리포트 전**        | 기록한 날(공부 또는 체크인한 날)이 14일 미만이면 리포트 대신 카운트다운 (`REPORT_MIN_DAYS`)            |
| 주 이름 "10월 3주"      | 그 주 목요일이 든 달 · 몇 번째 주                                                                      |
| 이번 주 발견 · 보기 3개 | 일찍 멈춘 타이머 → 폰 때문에 멈춤 → 다 못 채운 날 순서로 맞는 것 하나 (`findWeekFinding`)              |
| 고른 것의 결과          | 묻지 않고, 그 주 공부한 날 중 계획 완료한 날로 봄                                                      |

## 데이터는 어디서 오나요?

| 데이터                    | 어디에                                                                                  | 서버 API                                  |
| ------------------------- | --------------------------------------------------------------------------------------- | ----------------------------------------- |
| 공부 기록                 | 이 기기 + **서버의 최근 6개월**(진짜 로그인일 때 받아서 합침, `lib/historySessions.ts`) | `GET /study-sessions?from=&to=` (31일씩)  |
| 카드 · 체크인 · 휴식 표시 | 서버와 맞춰지는 이 기기 저장소                                                          | 이미 있음                                 |
| 사진 채점                 | 서버                                                                                    | `GET /answer-checks?date=` · `?from=&to=` |
| 확인 문제 결과            | 이 기기 (`quiz-results`)                                                                | `/quiz-results` (BE #375, FE 연결은 다음) |
| 이번 주에 고른 것         | 이 기기 (`weekly-picks`) + **서버**(진짜 로그인일 때 받아서 합침, 고르면 서버에도 저장) | `/weekly-picks` (BE #416, FE #654)        |
| 나 사용설명서 · 틀렸어요  | 이 기기 (`manual-items` · `manual-disputes`)                                            | BE #364 진행 중                           |

- 서버 기록을 합칠 때 같은 기록은 한 번만 셉니다: 이 기기에서 보낸 기록(`session-sync`)과 시작 시각이 1초 안인 기록은 이 기기 것만 씁니다.
- 받는 동안에는 이 기기 기록으로 먼저 그리고, 못 받으면 안내와 함께 이 기기 기록만 보여 줍니다.
- 고른 것은 같은 주면 서버 것을 씁니다. 이 기기에서 골랐는데 아직 못 보낸 주(`weekly-picks-unsent`)만 이 기기 것을 쓰고 다시 보냅니다.
  이 기기에만 있던 것(이 기능 전에 고른 것)은 기록 탭을 열 때 한 번 올리고, 시연 데이터(`demo-`)는 보내지 않습니다. (`lib/weeklyPicksApi.ts`)
  고른 것을 못 받으면 안내 없이 이 기기 것만 봅니다. 서버에 지우는 주소가 없어서 "모든 기록 지우기" 뒤에도 서버의 고른 것은 다시 보입니다.
