## 1. 왜 했나

- 과목 쌤에게 한국사 문제를 부탁하면 눌러 푸는 화면 대신 글로 문제가 나왔습니다.
- "한국사 문제 3개 내줘" 가 첫 번째엔 "주제를 더 자세히 적어 줘" 로 끝나고, 다시 하면 됐습니다.
- 카드 화면의 "계획 정확도" 줄과 "더 정하기" 칸을 쓰지 않습니다.
- 발표를 PC 로 하는데, 보여 주고 싶은 것은 휴대폰 화면입니다.

## 2. 문제가 글로 나오던 원인 — BE 배포가 밀려 있었음

FE 수정은 10/31 에 나갔지만 BE 는 나가지 못했습니다.

- BE 는 `render.yaml` 의 `autoDeployTrigger: checksPass` 라서 **GitHub Actions 검사가 통과해야 배포**됩니다.
- 10/31 에 조직의 Actions 무료 분량이 다 떨어져서 검사가 시작도 못 하고 실패했습니다.
- 달이 바뀌면 분량은 다시 채워지지만, **이미 실패한 검사를 저절로 다시 돌리지는 않습니다.** 새 커밋도 없어서 그대로 멈춰 있었습니다.
- 그래서 AI 가 옛 지시문대로 문제를 번호 목록 글로 썼습니다.

`gh run rerun` 으로 검사를 다시 돌리자 통과했고, 재실행만으로 Render 배포도 시작됐습니다.

```bash
gh run rerun <실패한 main 실행 번호> --repo Tmax-IT-Hope-School/Project-BE
```

재실행해도 몇 초 만에 실패하면 아직 한도가 안 풀린 것입니다. 조직 결제 설정을 보거나 Render 관리자에게 Manual Deploy 를 부탁합니다.

## 3. 무엇이 바뀌었나 (화면)

### 확인 문제를 못 받으면 한 번 더 받기 (#798)

- 서버가 문제 없이 답하면 학생이 다시 부탁하기 전에 한 번 더 받아 봅니다. (`requestQuizOrDemo`)
- 위기 안내 · 공부 자료 아님은 다시 물어도 같아서 다시 묻지 않습니다.
- 그래도 안 되면 주제 탓을 하지 않고 "문제를 만들다 잠깐 막혔어. 조금 있다가 다시 부탁해 줄래?" 라고 합니다.
- BE 도 AI 답을 10초에서 25초까지 기다리게 했습니다. (BE #476) FE 는 원래 30초까지 기다렸습니다.
- 10초 제한은 **가장 유력한 원인이고 확정은 아닙니다.** 운영 로그를 보지 못했습니다.

### 카드 화면 줄이기 (#799)

- 칸은 제목 · 언제 · 체크리스트만 남습니다. "계획 정확도" 줄과 "더 정하기" 칸을 지웠습니다.
- 새 카드는 기본값으로 저장하고, 고치는 카드는 전에 정한 값을 그대로 둡니다.
- 고를 칸이 없어진 "낮춘 이유" 검사, 정확도 계산, 설정의 "선택 입력칸" 도 지웠습니다.

**이 때문에 달라지는 것**

- 새 카드는 과목을 고를 수 없어서 과목별 통계에 묶이지 않습니다.
- 새 카드는 가장 최근 목표에 저절로 걸리는데, 화면에서 풀 수 없습니다.

제목에서 과목을 찾는 함수(`findSubjectInTitle`)가 이미 있어서, 필요하면 과목은 저절로 넣을 수 있습니다. 아직 하지 않았습니다.

### PC 에서도 375px 폰 화면 (#801)

**시연용 결정입니다.** CLAUDE.md 4장의 "PC 와 모바일 둘 다 지원" 과 다릅니다. 고친 파일은 `src/index.css` 하나입니다.

- `--breakpoint-sm` 등 5개를 `999rem` 으로 올려서 **`sm:` · `md:` · `lg:` 가 어떤 화면에서도 켜지지 않습니다.**
- 화면이 640px 이상이면 `#root` 를 가운데 375px 로 두고, 하단 탭 · 확인창 · 타이머 화면(`.fixed.inset-0` · `.inset-x-0` · `.inset-x-4`)도 같은 폭에 맞춥니다.
- 640px 보다 좁은 휴대폰은 화면 폭을 그대로 다 씁니다.

**되돌리는 법:** `src/index.css` 에서 `--breakpoint-*` 다섯 줄과 맨 아래 "PC 에서도 폰 폭으로" 칸을 지웁니다. 그 전까지 새 화면에 `sm:` 를 써도 보이지 않습니다.

### 통화 장면 녹화

PV 에 소리를 입히는 대신, 직접 쓰는 모습을 녹화해서 따로 트는 쪽을 생각하고 있습니다. 아직 시험하지 않았습니다.

- `Cmd+Shift+5` → 선택 부분 기록 → 옵션에서 내장 마이크 → **이어폰 없이 스피커로** 통화. 30초만 먼저 찍어 소리를 확인합니다.
- 학생 대사만 정해 두고 AI 답은 그대로 씁니다. 두세 번 찍어 고릅니다.
- **1388 은 "나 힘들어" 로는 뜨지 않습니다.** `src/lib/safetyBrake.ts` 의 위기 표현("사라지고 싶" 등)이어야 하고, 통화 중에는 AI 가 말로 안내한 뒤 **끊으면 결과 화면에** 번호가 뜹니다.
- **위기 표현이 잡히면 그 계정은 안전 모드가 켜지고 7일 동안 통화가 위로 위주로 바뀝니다.** 시연 계정으로 찍으면 발표 전에 그 기록을 지워야 합니다.

### 시연 계정 채팅 정리 (계획, 아직 실행하지 않음)

말풍선은 서버에 저장되지 않고 브라우저에만 있습니다. 설정의 "모든 기록 지우기" 는 다른 기록까지 지우므로 쓰지 않습니다.

1. 말풍선: 시연 브라우저 콘솔에서 지웁니다. 다른 탭을 닫고 실행하고, 다른 기기는 따로 합니다.
   ```js
   ;['study-coach-thread', 'study-chat-thread-plan', 'study-chat-thread-tutor'].forEach((key) =>
     localStorage.removeItem(key),
   )
   location.reload()
   ```
2. 서버 채팅 기록: 직접 테스트한 줄만 지우고, `seed_6m_rows` 에 있는 시드는 남깁니다. AI 가 테스트 대화 요약을 "지난 대화" 로 꺼내지 않게 하는 일입니다.
3. 평소 대화를 찍으려면: 위기 표현이 잡힌 음성 통화 기록과 알림함의 안내 메시지도 지웁니다. 지우지 않으면 그 통화 날부터 7일 동안 통화가 위로 위주로 흘러갑니다.

운영 DB 를 지우는 일이라 범위를 정한 뒤 실행합니다. 관리 강도 한도(`care_settings.max_care_level`)가 0 으로 남아 있는 것이 통화에 영향을 주는지도 그때 코드로 확인합니다.
